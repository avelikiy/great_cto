02 — Typography
Monospace is not the code font. It is the voice.
Rule 4 of our existing system already says mono means machine-truth — anything a person would select and paste. 115 uses against 9 for the display token. The landing's primary call to action is literally npx great-cto, a string you copy. Setting the whole page in it is finishing a decision we already made, not importing someone else's.
The constraint that shapes the scale
Geist Mono is vendored wght 400–500. There is no bold.
Above the axis the browser synthesises a smeared outline — the exact defect fixed in five board rules on 2026-09-01. So hierarchy is built from size and colour, never weight. This is a constraint that improves the result: a blueprint does not shout, it measures.
The ramp, in the face itself
the same 12 --fs-* tokens the board already ships
--fs-num-xl 521h 26m
--fs-title-l 22A section heading
--fs-base 15Running copy. Monospace at 15px with a 1.6 line-height reads comfortably for a paragraph; it is not a code block, it is the page.
--fs-body 14Controls, navigation, table cells
--fs-eyebrow 11Section label
Everything above is weight 500 or 400. Nothing is bold. Hierarchy comes from 52 → 22 → 15 → 14 → 11 and from ink, and the page still reads.
Ink, light ground
#111111  18.09:1 — headings, primary
#414141  9.78:1 — body
#737373  4.54:1 — captions, labels
Three steps that actually step — unlike the board's --text2/--text3, which differ by 5% and encode a hierarchy nobody can see.
What replaces bold
Size — the ramp above
Ink — three steps, not two
Rule — a 1px border under a heading
Fill — for one thing per screen
Four instruments. A page that needs a fifth is a page with too many claims on it.
