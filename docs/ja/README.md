---

great_cto は、**すでに動かしているコーディングエージェントを取り囲む層**です。あなたの
Claude Code をビルド全体にわたって駆動し、**あなたが所有するリポジトリ**と**すでに動いて
いる URL** を手渡します：アーキテクチャ、データモデル、バックエンド、フロントエンド、
生成されたテスト、そしてデプロイまで、完了した状態で。計画ではありません。プロトタイプ
でもありません。

プロンプト集にはできない、これだけの仕事：**エージェントが何をやらなかったかを告げる。**
飛ばされたステージ、一度も走らなかったレビュー、誰も測らなかったコスト — それぞれが
そのものとして表示され、合格として数えられることは決してありません。証拠は引き算です：
v3.27.0 と v3.27.1 は、このプロジェクト自身に有利な数字 —「FTE 比のコスト削減」、人間
チームとの支出比較、見込みの月額 — を削除しました。どれも真であると示せなかったからです。

Codex ではパイプラインは走りません。そこで動くのはスキル束と MCP サーバーです。Codex の
もう一つの役割は**セカンドオピニオン**であること — Claude Code の内側から同じ diff を読み、
レビュー行はそれぞれ読んだツリーの `sha` を持ちます。だから「レビュー済み」は*この* diff
について、主張ではなく証明できます。ログにあるのは**現時点で 4 行、うち 1 行が sha 付き**。
そこから検出率は主張しませんし、すべきでもありません。

ホスト型のアプリビルダーではなく、あなたのエージェントを置き換えるものでもありません。
エージェントがなければ、オーケストレーションする対象そのものがありません。

公開ベンチマークでエンドツーエンドに構築された 7 本のプロダクトは、トークン費で
**中央値 $171**（2026-07 実測）。支払先はあなた自身の LLM プロバイダで、great_cto は
あなたに何も請求しません。MIT です。

あなたが止められるのは**3 回**。**何を**作るか、**どう**作るか、そして**リリースするか**。
その間はすべて無人で進みます。そして、放っておくに値するものであることがパイプライン
自身の仕事です：役割の狭い専門家たち（architect、design-advisor、senior-dev、
code-reviewer、QA、security、devops）と、次のステージがその上に積み上げる前に各ステージ
の成果を検証する独立したモデル。全名簿は
[docs/reference/agents.md](../reference/agents.md) にあります。

```
   プロダクトを説明
        │
   🤖  問題の定式化 · 選択肢の比較 · ブリーフの作成
        ▼
   👤  チェックポイント 1 — 何を作るかを承認
        │
   🤖  アーキテクチャ · データモデル · 画面 · 計画
        ▼
   👤  チェックポイント 2 — どう作るかを承認
        │
   🤖  雛形 → バックエンド → フロントエンド → テスト → レビュー → セキュリティ
        ▼
   👤  チェックポイント 3 — デプロイを承認
        │
   🤖  デプロイ済み · リポジトリ · 公開 URL
```

3 回のチェックポイントは**デフォルト**であって、下限ではありません。`PROJECT.md` の 1 行で
1 回になります — 承認するのはデプロイだけになり、チェックポイント 1 と 2 は、記入する
フォームではなく読む画面に変わります：

```
approval-level: ship-only
```

[いつ聞かれるか](#いつ聞かれるか)を参照。

`localhost:3141` のボードは自動で埋まります — パイプラインの状態、承認待ちのゲート、
エージェント別コスト、30 日間の支出。餌をやる必要はなく、見るだけです。画面は 4 つ、
それぞれ問いはひとつ：**Decisions**（あなた待ちのもの — 全ゲートを両レビュアーの判定つき、
取り消しコスト順に）、**Ledger**（何にいくらかかり、いま何が走っているか）、**Fleet**
（どのエージェントを信用しなくなるべきか — そのツール権限、実行回数、支出）、**Harness**
（誰がホストで、誰がセカンドオピニオンを出し、それが実際に何をしたか）。設定は歯車の裏、
`⌘K` はエージェント・ドキュメント・セッション・記憶・決定を名前で引きます。ボード上の
どれ一つとして、不在を合格としては描きません — 一度も走らなかったスキャンは `n/a` であり、
緑のゼロではありません。

## 実測の数字

| | |
|---|---|
| 機能 1 件、エンドツーエンド、完全トレース付き | **1h 26m · $3.40**（トークン費）— [証跡](https://greatcto.systems/proof) |
| プロダクト丸ごと — 公開ベンチマークで 7 本構築 | 中央値 **$171**（トークン費）· 品質 **70/100**（58–86）、**2026-07-10** 実測 — [再現する](../benchmarks/BENCH-2026-07-batch1.md) |
| 標準的な月（パイプライン 20 回） | **~$34** — 支払先は自分の LLM プロバイダのみ、他はなし |
| 構築できるプロダクト | **60** 種、米国 15 業種、[再利用可能な 6 本のパイプライン](https://greatcto.systems/pipelines)経由 |

品質スコアは各プロダクト自身のテストを実行して算出します。ファイル数を数えるのではなく —
だから 70 という、丸くも綺麗でもない数字なのです。

## クイックスタート

```bash
npx great-cto init
```

Claude Code を再起動して：

```bash
/start "build a dispatch & scheduling app for an HVAC business"
```

あとはパイプラインが引き継ぎます。日常的に触るのは 3 つだけ：

| | |
|---|---|
| `/start "…"` | プロダクトや機能を説明 — パイプラインが実行 |
| `/inbox` | あなた待ちのもの：ゲート、P0、ブロック中タスク |
| `/digest` | 週次 DORA メトリクス + 機能あたりコスト |

Node ≥ 18.17 が必要。コンパニオンプラグイン（Superpowers、Beads）は自動で入ります。
init 後、ホストが本当にプラグインを読み込んだか確認してください —
`claude plugin list --json` で `great-cto` の `errors` が空であること。

**OpenAI Codex では**（`npx great-cto init --host codex`）**スキルと MCP サーバー**が
手に入ります — 上のパイプラインではありません。Codex にはフック、スラッシュコマンド、
ロールエージェントのためのプラグイン面がないため、`/start`、`/inbox`、ゲート連鎖、
`secret-scan` はそこでは動きません。これは設定ではなくホストの制約です：プラグイン
マニフェストの `hooks` は読まれることがありません
（[openai/codex#16430](https://github.com/openai/codex/issues/16430)、
[#39895](https://github.com/openai/codex/issues/39895)）。インストーラは何かをする前に、
同じ切り分けを表示します。

**ハーネスは 2 つ、レビューは 1 つ。** 3.26.0 以降、Codex は*実際に*パイプラインに参加
します — Claude Code の内側から、2 人目のレビュアーとして。宣言は一度だけ：

```yaml
# .great_cto/PROJECT.md
capabilities:
  second_opinion: codex      # or: openrouter · none
```

これで、影響の大きい変更のたびに Claude の `code-reviewer` と **`codex exec`**（読み取り
専用サンドボックス、あなたの Codex ログイン、API キー不要）が**同じ diff を同時に**
レビューします。指摘は統合され、どちらか一方からの P0 でもブロック。意見が割れた場合は
両方の指摘がゲートで人間に届き、厳しい方が判定を決めます。平均を取る者はいません。ボードの
**Harness** 画面は Codex を検出し、選択を保持し、その横にセカンドオピニオンが*何をしたか*
を表示します：`.great_cto/cross-review.log` から、スキップされた回も含めて全実行を。状態は
4 つで、4 つ目が肝心です — *宣言されているが到達不能*が*オフ*として表示されることは
決してありません。

どれだけ役に立つかは、ここで主張するのではなく、そこで測られます。ログに現時点であるもの：
最初の実 Codex レビュー — Codex を組み込んだコミット自体のレビュー — は、作者もテスト
スイートも見落としていた P1 を見つけました。その修正のレビューでは何も見つかりませんでした。
2 回は仕組みの証拠であって、率ではありません。率を出すのはカードの仕事です。

## いつ聞かれるか

`.great_cto/PROJECT.md` の設定ひとつで、パイプラインの停止位置が決まります：

| `approval-level` | 止められる場所 | 停止回数 |
|---|---|---|
| **`ship-only`** | **デプロイ — そして何が作られるかの説明を受ける** | **1** |
| `product-only` | 何を作るか · リリースするか | 2 |
| `gates-only` *(デフォルト)* | 何を作るか · 設計 · デプロイ | 3 |
| `strict` | 設計 · コードレビュー · デプロイ | 3 |
| `auto` | パイプライン内では何もなし | 0 |

数はパイプラインの停止回数です。どのレベルにも、プロセス上の選択ではないガードが 1 つ
付いてきます：既存レコードへの上書きを伴うデータ取り込みは、`auto` を含む**すべての**
レベルであなたを止めます。それだけは、そこにあったものを破壊するからです。

**`ship-only` は、なお誠実でいられる最小値です。** 停止は 1 回 — デプロイ、つまり結果が
あなたのマシンの外へ出る唯一の決定です。*何を作るか*の決定が消えるわけではありません。
間違ったものに丸一日を費やすパイプラインこそが高くつく失敗だからです：それはコンソールに
1 画面として、ビルド開始前に一度だけ表示されます。

```
ABOUT TO BUILD — say nothing and this proceeds, say something and it stops.

  What gets built:  the offline-first checkout; ship the queue before the UI
  Why:              reliability wins this segment, not features
  Stop if:          under 20% of orders are created offline after four weeks
  Left open:        which conflict rule for a re-submitted order

  Full brief: docs/product/BRIEF-checkout.md
```

沈黙は同意であり、画面自身がそう言っています。ブリーフが読めなかった場合はゲートが
戻ってきます —「お見せできませんでした」が「お見せしたのに何も言わなかった」として
届けられることはありません。

`gates-only` がプロダクトゲートを得たのは v3.0.0 です。それ以前は*どう*作るかと
*リリースするか*で止まり、*何を*作るかでは止まりませんでした — 6 ステージ先まで誰も
気づかないまま間違い続ける、あの決定です。コストは**プロダクト**あたり 1 回の停止で、
機能あたりではありません：`product-owner` はエントリポイントであり、`/start` からのみ
走ります。

規制対象のアーキタイプ — フィンテック、医療、行政 — は、セキュリティ・コンプライアンス・
リリースのゲートを **`auto` を含む全レベルで**保持します。軽いレベルは判断の委任であって、
コンプライアンスの省略ではありません。全表：[docs/GATES.md](../GATES.md)。

## 口にしないと決めた 4 つのこと

同じ一つの規則を、守るのに手間のかかる 4 か所で貫いています：**起きなかったことが、
起きたことのように見えてはならない。**

| 場面 | 見せるのが簡単なもの | 代わりに見せるもの |
|---|---|---|
| セカンドオピニオンが宣言されているのに、そのハーネスがない | *オフ* | **`unavailable`** — 宣言済みかつ到達不能は、あなたがした選択ではない |
| チェックは走ったが判断できなかった | *合格* | **`unverifiable`** — そしてステージはそれを根拠に先へ進まない |
| 実行のコストが一度も測られなかった | **`$0.00`** | **`unmeasured`** — そして予算はそれで発火しない |
| ステージを誰も評価しなかった | *0* | **`null`** — 合格率は、実際に評価された数で割る |

どれも、正直な答えのほうが長く、不格好で、自信ありげな答えより作るのが難しい場所です。
それがこのプロダクトのすべてです。

## 持つに値する 3 つの疑い

**「書かれるところを見ていないコードは信用できない」**
こちらも信用していません。だからエージェントの自己申告は一切当てにしません。各ステージは
実際に生み出したものに照らして検証されます — 名前を挙げたファイルは存在するか、凍結された
受け入れ基準は実行して通るか。そのうえで初めて、各要件が満たされているかを別のモデルに
問います。その検証が判断できないときは `unverifiable` を返します。これは合格では
**ありません**。

**「私が寝ている間にお金を使うだろう」**
エージェント別の予算は上限を超えた起動を拒否し、その数字を明示します。コストが測れなかった
実行は `unmeasured` と表示され、何も保持しません — 誰も測っていない数字で上限が発火するのは、
上限がないより悪く、測っていない作業に自信ありげな `$0.00` を出すことこそ、支出が見過ごされる
仕組みだからです。

**「そして囲い込まれる」**
インストールはコマンド 1 つ、MIT、あなたのマシンで、あなた自身の LLM アカウントに対して
動きます。great_cto を消しても、それが作ったリポジトリはあなたのものです — どのエンジニア
でも引き継げる、ごく普通の Next.js、Postgres、Stripe です。

## 何が違うか

- **ゼネラリストではなくスペシャリスト** — 役割の狭い 70 エージェントが各自のレビュー
  ゲートを持つ。考えるより速くタイプするアシスタント 1 体ではなく。
  [名簿 →](../reference/agents.md)
- **コードの前に批評家** — アーキテクチャ・仕様・スキーマの批評家が計画前に走る。誤りの
  修正コストがまだ日単位ではなく時間単位のうちに。
- **書き込み時点でスコープを強制** — エージェントは担当外のファイルに物理的に触れない。
  レビューで指摘ではなく、書き込みで拒否。
- **自分を疑う QA** — クリティカルパスをまず Gherkin で書き、それからテストコード。さらに
  ミューテーションテストが問う：このスイートは何か捕まえられるのか。
- **セッションを跨ぐ記憶** — 決定・教訓・昇格したパターンがプロジェクト別とグローバルに
  永続化。中断した実行は、どのステージが済んだか知った上で再開。
- **見えるコスト** — エージェント別支出、見積と実績の乖離、承認された変更あたりのコスト。
  ボード上に、スプレッドシートではなく。
- **拒否する支出上限** — PROJECT.md の `agent-budgets:` がステージの使える額を上限で
  縛り、パイプラインはそれを超える起動を拒否して数字を明示する。見積は決して拒否しない —
  上の表を参照。
- **次が積み上げる前にステージを検証** — 判定が名指ししたファイルは存在しなければならず、
  凍結された `## ACCEPTANCE` 基準は実行して通らなければならず、そのうえで初めて、各要件が
  満たされているかを 2 つ目のモデルに問う。安い問いから順に、答えは 2 つではなく 3 つ：
  `verified`、`rework`、`unverifiable`。何も主張せず基準も凍結しないエージェントは
  報告される — さもなければ、何も主張しないことが最も安い合格法になってしまう。
- **仕事は差し戻され、その往復には上限がある** — 失敗したステージは指摘を引用した
  `REWORK` とともに戻り、同じエージェントが直す。`BLOCKED` は人間が決めるべきという意味。
  3 巡したら人間の問題になる。機械 2 台は仕事を投げ合っても飽きないからだ。
- **品質は「何が起きたか」と切り離す** — 判定は実行が何をしたかを言い、*スコア*はどれだけ
  よくできたかを言う。別の主体が別の時点で、追記専用の独自ストアに書く。採点者どうしは
  食い違ってよく、どのスコアも誰が付けたかを名指しする。
- **沈黙が記録される** — ディスパッチャは自分が何を決めたかを
  `.great_cto/pipeline-runs.jsonl` に書く。*何も決めなかったときも*、その理由とともに。
  今年見つかったパイプラインの欠陥はすべて、「何も起きないはず」と「何も起こせなかった」の
  隙間に隠れていた。

すべてローカルで動作、MIT ライセンス、鍵は自分のもの。コードはあなたのマシンに留まり、
プロンプトはあなたの LLM プロバイダにのみ送られ、他のどこにも行きません。テレメトリは
**デフォルトで無効**（[docs/PRIVACY.md](../PRIVACY.md)）。

## 制約

- **単独ビルダー向け** — ソロ創業者か CTO。エンジニア 2 名以上でパイプラインを共用する
  段階なら、もう卒業です。
- **CI/CD ではない** — ゲートはローカル実行。マージは引き続き GitHub Actions。
- **認証監査ではない** — PCI/HIPAA/SOC2 の雛形は出発点であって認証ではない。
- **決定的ではない** — LLM の出力。ゲートの判定は目視確認に値します。
- **支出は測っているが、エージェント別の帰属はまだ** — コストはエージェントの自己申告
  ではなくホスト自身のセッション記録から読むので、トークンは実数です。ただしフックに
  渡される記録はセッション全体を覆っており、サブエージェント 1 体分ではありません。その
  ため、ある実行のコストが最後に終わったステージに帰属してしまうことがあり、桁違いに
  膨らみます。これが直るまで、エージェント別の数字は上限値として扱ってください。まったく
  測定のないステージは、自信ありげな `$0.00` ではなく `unmeasured` と表示され、予算も
  発火しません。
