great_cto — **слой оркестрации над кодинг-агентом, которым вы уже пользуетесь**.
Пайплайн из **69 специализированных агентов** — architect, design-advisor,
senior-dev, code-reviewer, QA, security, devops — планирует, строит, ревьюит и
деплоит настоящее приложение: бэкенд, фронтенд, сгенерированные тесты, живой URL.

Вас останавливают ровно дважды: один раз на **что строим**, один раз на
**выкатываем ли**. Всё между этими точками идёт без вас.

```
   опишите продукт
        │
   🤖  спека · архитектура · модель данных · экраны
        ▼
   👤  чекпоинт 1 — одобрить ЧТО строим
        │
   🤖  architecture · data model · screens
        ▼
   👤  чекпоинт 2 — одобрить КАК строим
        │
   🤖  каркас → бэкенд → фронтенд → тесты → ревью → безопасность
        ▼
   👤  чекпоинт 3 — одобрить деплой
        │
   🤖  задеплоено · репозиторий · живой URL
```

## Цифры, измеренные

|---|---|
| Одна фича, от идеи до PR, с полной трассировкой | **1ч 26м · $3.40** в токенах — [чеки](https://greatcto.systems/proof) |
| Целый продукт — 7 штук в открытом бенчмарке | медиана **$171** в токенах · качество **70/100** (58–86) — [воспроизвести](../benchmarks/BENCH-2026-07-batch1.md) |
| Типичный месяц, 20 прогонов пайплайна | **~$34** — вы платите своему LLM-провайдеру и больше никому |
| Продуктов, которые система умеет строить | **60**, в 15 индустриях США, через [6 переиспользуемых пайплайнов](https://greatcto.systems/pipelines) |

Оценка качества получается запуском тестов самого продукта, а не подсчётом
файлов — поэтому она 70, а не более круглое и красивое число.

## Быстрый старт

```bash
npx great-cto init            # Claude Code (по умолчанию) · --host codex для OpenAI Codex
```

Перезапустите AI-хост, затем:

```bash
/start "построй приложение диспетчеризации для HVAC-бизнеса"
```

Дальше пайплайн ведёт сам. В повседневной работе вы касаетесь трёх вещей:

| | |
|---|---|
| `/start "…"` | опишите продукт или фичу — пайплайн её выполнит |
| `/inbox` | что ждёт вас: гейты, P0, заблокированные задачи |
| `/digest` | недельные DORA-метрики + стоимость на фичу |

Нужен Node ≥ 18.17. Плагины-компаньоны (Superpowers, Beads) ставятся сами.
После init проверьте, что хост реально загрузил плагин: в
`claude plugin list --json` у `great_cto` не должно быть `errors`.

## Когда система спрашивает вас

Одна настройка в `.great_cto/PROJECT.md` решает, где пайплайн останавливается:

| `approval-level` | Останавливается на | На фичу |
|---|---|---|
| `product-only` | что строим · выкатываем ли | 2 |
| `gates-only` *(по умолчанию)* | дизайн · деплой | 2 |
| `strict` | + код-ревью | 3 |
| `auto` | ничего | 0 |

Регулируемый архетип — финтех, здравоохранение, госсектор — держит гейты
безопасности, комплаенса и деплоя **на любом уровне, включая `auto`**. Более
лёгкий уровень делегирует суждение, но никогда не обходит комплаенс. Полная
таблица: [docs/GATES.md](../GATES.md).

## Чем отличается

- **Специалисты, а не генералист** — 69 агентов с узкими ролями и своими
  гейтами ревью, вместо одного ассистента, который печатает быстрее, чем
  думает. [Состав →](../reference/agents.md)
- **Критики до кода** — критики архитектуры, спеки и схемы работают до
  планирования, где ошибка ещё стоит часы, а не дни.
- **Скоуп на записи** — агент физически не может тронуть файлы вне своего
  задания. Не помечается на ревью — отклоняется при записи.
- **QA, который не верит сам себе** — критические пути описываются на Gherkin
  до кода тестов, затем мутационное тестирование спрашивает, поймает ли сюита
  хоть что-нибудь.
- **Память между сессиями** — решения, уроки и продвинутые паттерны живут по
  проектам и глобально; прерванный прогон возобновляется, зная, какие стадии
  уже прошли.
- **Видимая стоимость** — расход по агентам, дрейф смета-против-факта и
  стоимость принятого изменения — на доске, а не в таблице.

Всё работает локально, лицензия MIT, ваши ключи. Код остаётся на вашей машине;
промпты уходят вашему LLM-провайдеру и больше никуда. Телеметрия **выключена по
умолчанию** ([docs/PRIVACY.md](../PRIVACY.md)).

## Ограничения

- **Для одного строителя** — соло-основателя или CTO. Двое и больше инженеров
  на одном пайплайне — вы его переросли.
- **Не CI/CD** — гейты работают локально; мерж по-прежнему через GitHub Actions.
- **Не сертификация** — каркасы PCI/HIPAA/SOC2 — отправная точка, не аудит.
- **Не детерминизм** — вывод LLM. Вердикты гейтов заслуживают проверки глазами.
