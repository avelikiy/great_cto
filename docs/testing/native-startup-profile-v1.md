# Native startup profile v1

Frozen before implementation under [ADR-046](../adr/ADR-046-native-plugin-activation.md).
This source stage prepares an inactive bounded context loader and a complete
hook-effect inventory. It does not select a new manifest or activate a host.

Done when: the real Node entrypoint, started in an owned project with network
denied, produces bounded private context without filesystem writes or children;
symlinked, hard-linked, oversized, changed or noncanonical inputs are refused;
every existing hook command has an event/matcher/position/hash identity; mandatory
guards remain accounted for, and unresolved effects keep activation unsupported.

Assumption A1: admitted immutable plugin bytes and a separately selected canonical
project root are inputs to a future adapter. A path or an inventory result is not
artifact admission. The context loader itself grants no capability.

The context loader uses only Node standard-library filesystem/path/url modules.
It never invokes a shell, Git, bd, a package manager, downloader, provider or child
process; it does not write context, traces, credentials or registries. Do not read
HOME caches, preference files, dotenv or secret stores. Read only the selected
plugin's operating-rules.md and the selected project's PROJECT.md, brain.md,
CODEBASE.md, HANDOFF.md and local.md as applicable to its declared phase.

Require explicit absolute canonical project and plugin roots, distinct roots and
a regular PROJECT.md under a real .great_cto directory. Refuse symlinked final
files/directories and files with multiple hard links. Read through an opened
descriptor with O_NOFOLLOW, bounded at65536bytes per file and131072bytes total;
compare descriptor identity/size/mtime before and after reading. This does not
claim atomic snapshots against same-user concurrent writes or directory races.
Context files are untrusted data, never installation, registry or gate authority.

Only planning, implementation, review and release phases select additional
context. Unknown/absent phase remains unknown; do not invent task/gate counts.
Every returned document has a relative allowlisted name and a byte digest.
Private document text belongs only in hookSpecificOutput.additionalContext.
Public metadata contains no document body, absolute path or environment values.
The serialized hook reply is bounded at262144bytes. Drain stdout; no immediate
process.exit. Refusals use fixed reason codes and return no partial document text.

Inventory all primary hook commands in manifest order, with event, matcher,
entry/command index, timeout presence and exact SHA256. Retain every non-startup
guard and its matcher/order. Do not filter away unknown hook types/extensions;
report a refusal. The existing 54-command manifest is a source fixture, not an
evergreen expected count: detect additions/removals against a bound snapshot.
Replacing the monolithic context convenience must never imply that gate expiry,
graph observation, project registration, state writes, resume, reviewer guidance,
managed-file synchronization or runtime dependencies have been accepted.

Prepare a separate environment inspector for future child execution: accept only
explicitly named variables; refuse loader/preload and shell initialization
variables, conflicting plugin roots and unexpected config authority. Never
publish rejected values, provider values or key tails. Environment inspection is
not runtime admission and must not mutate process.env or operator settings.

Acceptance uses real owned filesystem fixtures: missing/poisoned roots, links,
FIFO/special-file refusal without blocking, size and total bounds, malformed
phase, exact selected-file reads, unchanged directory membership/bytes/modes,
large stdout, generic failures with no partial context, and no global reads or
network/child acquisition. Hook inventory tests exercise matcher/order/command
mutation and every mandatory guard. Environment tests exercise prototype keys,
preloads, config aliases and credential privacy. No operator keys or paid calls.

Run focused regressions, source/docs/security checks and the canonical gate.
Generated architecture counts may be regenerated by the standard generator for
new modules; do not change unrelated graph content. Independent source review
and actual isolated native N01-N20 remain separate required steps. The native
admission result stays unsupported throughout this inactive preparation.
