**당신의 코딩 에이전트는 코드를 출시합니다. 이것은 그것을 검사하는 물건입니다.**

당신이 스펙을 씁니다. 당신의 Claude Code가 그 스펙에 맞춰 빌드하고, 다른 계열의
두 번째 모델이 같은 diff를 읽습니다. 둘의 의견이 갈리면 그 불일치를 당신이 보고
결정합니다. 세 가지 결정은 계속 당신 것입니다 — 무엇을 만들지, 어떻게 만들지,
그리고 출시할지. 남는 것은 **당신 소유의 저장소**와 **동작하는 URL**입니다.

공개 벤치마크에서 이렇게 만든 제품 일곱 개의 토큰 비용은 **중앙값
$171**이었습니다(2026-07-10 측정). LLM 제공사 요금은 본인이 냅니다. great_cto는
MIT이고 아무것도 청구하지 않습니다.

```
   제품을 설명
        │
   🤖  문제 규정 · 선택지 비교 · 브리프 작성
        ▼
   👤  체크포인트 1 — 무엇을 만들지 승인
        │
   🤖  아키텍처 · 데이터 모델 · 화면 · 계획
        ▼
   👤  체크포인트 2 — 어떻게 만들지 승인
        │
   🤖  스캐폴드 → 백엔드 → 프런트엔드 → 테스트 → 리뷰 → 보안
        ▼
   👤  체크포인트 3 — 배포 승인
        │
   🤖  배포 완료 · 저장소 · 라이브 URL
```

정지 세 번은 기본값이지 하한선이 아닙니다. 한 줄이면 하나로 줄어듭니다:

```
approval-level: ship-only
```

`localhost:3141`의 보드는 스스로 채워집니다 — **Decisions**(당신이 필요한 것),
**Ledger**(무엇에 얼마가 들었는지), **Fleet**(어떤 에이전트를 더는 믿지 말아야
하는지), **Harness**(누가 세컨드 오피니언을 냈고, 그것이 실제로 무엇을 했는지).
이 보드에서 부재가 통과로 렌더링되는 곳은 하나도 없습니다 — 실행되지 않은 스캔은
`n/a`이지, 초록색 0이 아닙니다.

## 측정된 숫자

| | |
|---|---|
| 기능 1건, 엔드투엔드, 전체 추적 가능 | **1h 26m · $3.40** 토큰 비용 — [영수증](https://greatcto.systems/proof) |
| 완제품 — 공개 벤치마크에서 7개 구축 | 중앙값 **$171** 토큰 비용 · 품질 **70/100**(58–86), **2026-07-10** 측정 — [직접 재현](../benchmarks/BENCH-2026-07-batch1.md) |
| 일반적인 한 달, 파이프라인 20회 실행 | **~$34** — 지불 대상은 본인의 LLM 제공사뿐 |
| 구축할 줄 아는 제품 | **60**종, 미국 15개 산업, [재사용 가능한 6개 파이프라인](https://greatcto.systems/pipelines) 경유 |

품질 점수는 각 제품 자체의 테스트를 실행해 산출합니다. 파일 개수를 세는 것이
아니라 — 그래서 더 둥글고 예쁜 숫자가 아니라 70인 것입니다.

## 빠른 시작

```bash
npx great-cto init
```

Claude Code를 재시작한 뒤:

```bash
/start "build a dispatch & scheduling app for an HVAC business"
```

이후는 파이프라인이 이어받습니다. 일상적으로 만지는 것은 세 가지뿐입니다:

| | |
|---|---|
| `/start "…"` | 제품이나 기능을 설명 — 파이프라인이 실행 |
| `/inbox` | 당신을 기다리는 것: 대기 중인 게이트, P0, 블로킹된 작업 |
| `/digest` | 주간 DORA 지표 + 기능당 비용 요약 |

Node ≥ 18.17 필요. 동반 플러그인(Superpowers, Beads)은 자동 설치됩니다. init 후
호스트가 플러그인을 실제로 로드했는지 확인하세요 — `claude plugin list --json`에
`great-cto`의 `errors`가 없어야 합니다.

**OpenAI Codex에서는**(`npx great-cto init --host codex`) **스킬과 MCP 서버**만
얻습니다 — 위의 파이프라인은 아닙니다. Codex에는 훅·슬래시 커맨드·역할 에이전트를
위한 플러그인 표면이 없어서 `/start`, `/inbox`, 게이트 체인, `secret-scan`은 거기서
돌지 않습니다. 이것은 설정이 아니라 호스트의 한계입니다: 플러그인 매니페스트의
`hooks`는 읽히지 않습니다
([openai/codex#16430](https://github.com/openai/codex/issues/16430),
[#39895](https://github.com/openai/codex/issues/39895)). 설치 프로그램도 아무것도
하기 전에 같은 구분을 출력합니다.

**하니스 둘, 리뷰 하나.** Codex에서는 파이프라인이 돌지 않습니다. 거기서 도는 것은
스킬 번들과 MCP 서버입니다. Codex의 다른 역할은 **세컨드 오피니언**입니다 — Claude
Code 안에서 같은 diff를 읽고, 리뷰의 각 줄은 자신이 읽은 트리의 `sha`를 달고
있습니다. 그래서 "리뷰했다"를 주장이 아니라 *이* diff에 대해 증명할 수 있습니다.
로그에 쌓인 것은 **지금까지 4줄, 그중 sha가 붙은 것은 1줄**. 여기서 어떤 검출률도
주장하지 않고, 주장해서도 안 됩니다.

3.26.0부터 Codex는 그 두 번째 리뷰어로 파이프라인에 참여합니다. 한 번만 선언하면
됩니다:

```yaml
# .great_cto/PROJECT.md
capabilities:
  second_opinion: codex      # or: openrouter · none
```

이렇게 하면 위험이 큰 변경마다 Claude의 `code-reviewer`와 **`codex exec`**(읽기 전용
샌드박스, 당신의 Codex 로그인, API 키 없음)가 **같은 diff를 같은 시각에**
리뷰합니다. 발견 사항은 병합되고, 어느 쪽에서든 P0가 나오면 막습니다. 의견이
갈리면 양쪽 모두가 게이트에서 사람에게 도달합니다 — 더 엄격한 쪽이 판정을 정하며,
아무도 평균을 내지 않습니다. 보드의 **Harness** 화면은 Codex를 감지하고, 선택을
보관하고, 그 옆에 세컨드 오피니언이 *무엇을 했는지* 보여줍니다:
`.great_cto/cross-review.log`에 담긴 모든 실행, 건너뛴 것까지 포함해서. 상태는 넷,
그리고 네 번째가 핵심입니다 — *선언됐으나 사용할 수 없음*은 결코 *꺼짐*으로
표시되지 않습니다.

얼마나 도움이 되는지는 여기서 주장하는 게 아니라 거기서 측정됩니다. 지금까지 로그에
있는 것: 첫 실제 Codex 리뷰 — Codex를 연결한 그 커밋에 대한 리뷰 — 는 작성자와
테스트 스위트가 둘 다 놓친 P1을 찾아냈고, 그 수정에 대한 리뷰는 아무것도 찾지
못했습니다. 두 번의 실행은 메커니즘의 증거이지 비율이 아닙니다. 비율은 그 카드가
할 일입니다.

## 언제 물어보는가

`.great_cto/PROJECT.md`의 설정 하나가 파이프라인이 멈추는 위치를 결정합니다:

| `approval-level` | 멈춰 세우는 지점 | 정지 횟수 |
|---|---|---|
| **`ship-only`** | **배포 — 그리고 무엇을 만들지 브리핑합니다** | **1** |
| `product-only` | 무엇을 만들지 · 배포할지 | 2 |
| `gates-only` *(기본값)* | 무엇을 만들지 · 설계 · 배포 | 3 |
| `strict` | 설계 · 코드 리뷰 · 배포 | 3 |
| `auto` | 파이프라인 안에서는 없음 | 0 |

횟수는 파이프라인 정지 횟수입니다. 모든 레벨은 프로세스 선택이 아닌 가드 하나를
함께 가집니다: 기존 레코드 위에 데이터를 임포트하는 작업은 `auto`를 포함한
**모든** 레벨에서 당신을 멈춰 세웁니다. 그것 하나만은 거기 있던 것을 파괴하기
때문입니다.

**`ship-only`은 정직함을 유지하는 최소치입니다.** 정지는 하나 — 배포, 결과가 당신의
머신을 떠나는 유일한 결정. *무엇을 만들지*라는 결정이 사라지는 것은 아닙니다. 하루를
잘못된 것에 쓰는 파이프라인이야말로 비싼 실패이기 때문입니다: 그 결정은 빌드가
시작되기 전에, 콘솔에 한 번 출력되는 화면 하나로 도착합니다.

```
ABOUT TO BUILD — say nothing and this proceeds, say something and it stops.

  What gets built:  the offline-first checkout; ship the queue before the UI
  Why:              reliability wins this segment, not features
  Stop if:          under 20% of orders are created offline after four weeks
  Left open:        which conflict rule for a re-submitted order

  Full brief: docs/product/BRIEF-checkout.md
```

침묵은 동의이고, 화면이 그렇게 말합니다. 브리프를 읽을 수 없으면 게이트는 다시
돌아옵니다 — "보여드리지 못했습니다"가 "보여드렸는데 아무 말도 없었습니다"로
전달되는 일은 없습니다.

`gates-only`는 v3.0.0에서 제품 게이트를 얻었습니다. 예전에는 *어떻게* 만들지와
*릴리스할지*에서만 멈추고, *무엇을* 만들지에서는 결코 멈추지 않았습니다 — 아무도
알아채기 전에 여섯 단계 동안 틀린 채로 굴러가는 그 결정에서 말입니다. 비용은 기능당이
아니라 **제품당** 한 번의 멈춤입니다: `product-owner`는 진입점이고 `/start`에서만
실행됩니다.

규제 대상 아키타입 — 핀테크, 헬스케어, 공공 — 은 **`auto`를 포함한 모든 레벨에서**
보안·컴플라이언스·배포 게이트를 유지합니다. 가벼운 레벨은 판단을 위임하는 것이지,
컴플라이언스를 건너뛰는 것이 아닙니다. 전체 표: [docs/GATES.md](../GATES.md).

## 말하기를 거부하는 네 가지

같은 규칙을, 지키는 데 대가가 따르는 네 곳에서: **일어나지 않은 일이 일어난 일처럼
보여서는 결코 안 된다.**

| 언제 | 보여주기 쉬운 것 | 대신 보여주는 것 |
|---|---|---|
| 세컨드 오피니언이 선언됐는데 그 하니스가 없을 때 | *off* | **`unavailable`** — 선언됐는데 닿지 않는 것은 당신이 내린 선택이 아닙니다 |
| 검사가 실행됐으나 판단할 수 없었을 때 | *pass* | **`unverifiable`** — 그리고 그 단계는 이대로 진행되지 않습니다 |
| 실행 비용이 한 번도 측정되지 않았을 때 | **`$0.00`** | **`unmeasured`** — 그리고 예산은 여기에 발동하지 않습니다 |
| 어떤 단계를 아무도 평가하지 않았을 때 | *0* | **`null`** — 통과율은 실제로 평가된 것으로 나눕니다 |

이 각각은 정직한 답이 더 길고, 더 못생기고, 자신 있는 답보다 만들기 어려운
지점입니다. 그것이 이 제품의 전부입니다.

증거는 뺄셈입니다. v3.27.0과 v3.27.1은 이 프로젝트 자신에게 유리한 숫자들 — "FTE
대비 비용 절감", 사람 팀과의 지출 비교, 예상 월 비용 — 을 삭제했습니다. 어느 것도
참임을 보일 수 없었기 때문입니다.

## 가져볼 만한 세 가지 의심

**"내가 작성 과정을 지켜보지 않은 코드는 믿을 수 없다."**
우리도 믿지 않습니다. 그래서 에이전트가 자기 자신에 대해 한 말은 아무것도 그대로
받아들이지 않습니다. 각 단계는 실제로 만들어낸 결과와 대조해 검사됩니다 — 이름을 댄
파일이 존재하는지, 동결된 인수 기준이 실행했을 때 통과하는지, 그리고 그다음에야
별도의 모델에게 각 요구사항이 다뤄졌는지 묻습니다. 그 검사가 판단할 수 없는
경우에는 `unverifiable`을 돌려주며, 이것은 통과가 **아닙니다**.

**"내가 자는 동안 돈을 쓸 것이다."**
에이전트별 예산은 상한을 넘는 디스패치를 거절하고 그 숫자를 말합니다. 비용을 측정할
수 없었던 실행은 `unmeasured`로 표시되고 아무것도 붙잡지 않습니다 — 아무도 측정하지
않은 숫자에 발동하는 한도는 한도가 없는 것보다 나쁘고, 측정되지 않은 작업에 붙은
자신만만한 `$0.00`이야말로 지출이 눈에 띄지 않게 되는 경로입니다.

**"그리고 나면 종속된다."**
설치는 명령 하나, MIT, 당신의 머신에서 당신의 LLM 계정으로 돌아갑니다. great_cto를
지워도 그것이 만든 저장소는 여전히 당신 것입니다 — 어떤 엔지니어든 이어받을 수 있는
평범한 Next.js, Postgres, Stripe입니다.

## 무엇이 다른가

- **제너럴리스트가 아닌 스페셜리스트** — 좁은 역할과 자체 리뷰 게이트를 가진 70개
  에이전트. 생각보다 타이핑이 빠른 어시스턴트 하나가 아니라.
  [명단 →](../reference/agents.md)
- **코드 전에 비평가** — 아키텍처·스펙·스키마 비평가가 계획 전에 실행됩니다. 실수의
  값이 아직 며칠이 아니라 몇 시간일 때.
- **쓰기 시점에 강제되는 범위** — 에이전트는 자기 담당 밖의 파일을 물리적으로 건드릴
  수 없습니다. 리뷰에서 지적하는 게 아니라 쓰기에서 거부합니다.
- **자신을 의심하는 QA** — 핵심 경로를 테스트 코드보다 먼저 Gherkin으로 쓰고, 그다음
  뮤테이션 테스트가 묻습니다: 이 스위트가 뭐라도 잡아낼 수 있는가.
- **세션을 넘는 기억** — 결정·교훈·승격된 패턴이 프로젝트별로, 또 전역으로
  유지됩니다. 중단된 실행은 어떤 단계가 돌았는지 알고 재개합니다.
- **보이는 비용** — 에이전트별 지출, 견적 대비 실제의 편차, 승인된 변경당 비용이
  스프레드시트가 아니라 보드에 있습니다.
- **거절하는 지출 한도** — PROJECT.md의 `agent-budgets:`가 한 단계가 쓸 수 있는 양에
  상한을 겁니다. 파이프라인은 그것을 넘는 디스패치를 거절하고 그 숫자를 말합니다.
  견적은 결코 거절하지 않습니다 — 위의 표를 보세요.
- **다음 단계가 쌓기 전에 검사되는 단계** — 판정이 이름을 댄 파일이 존재해야 하고,
  동결된 `## ACCEPTANCE` 기준이 실행했을 때 통과해야 하며, 그다음에야 두 번째 모델이
  각 요구사항이 다뤄졌는지 답합니다. 가장 싼 질문부터, 그리고 답은 둘이 아니라 셋:
  `verified`, `rework`, `unverifiable`. 아무것도 주장하지 않고 아무 기준도 동결하지
  않은 에이전트는 보고됩니다 — 그러지 않으면 통과하는 가장 싼 방법이 아무것도
  주장하지 않는 것이 되니까요.
- **작업은 되돌아가고, 되돌아감에는 천장이 있다** — 실패한 단계는 발견 사항을 인용한
  `REWORK`로 돌아가고 같은 에이전트가 고칩니다. `BLOCKED`는 사람이 결정해야 한다는
  뜻입니다. 세 번을 넘기면 사람의 문제가 됩니다. 기계 둘이 서로 작업을 주고받는 일은
  지겨워지지 않으니까요.
- **품질은 일어난 일과 따로 둔다** — 판정은 어떤 실행이 무엇을 했는지 말하고,
  *점수*는 얼마나 잘했는지를 말합니다. 점수는 다른 행위자가 다른 시각에, 추가 전용
  저장소에 기록합니다. 채점자끼리 의견이 갈릴 수 있고, 모든 점수는 누가 매겼는지
  이름을 답니다.
- **침묵도 기록된다** — 디스패처는 자신이 무엇을 결정했는지를
  `.great_cto/pipeline-runs.jsonl`에 씁니다. *아무것도 결정하지 않았을 때도*, 그
  이유와 함께. 올해 발견된 모든 파이프라인 결함은 "아무 일도 일어나면 안 된다"와
  "아무 일도 일어날 수 없었다" 사이의 틈에 숨어 있었습니다.

모든 것이 로컬에서, MIT 라이선스로, 본인의 키로 동작합니다. 코드는 당신의 머신에
남고, 프롬프트는 당신의 LLM 제공사에게만 갑니다. 텔레메트리는 **기본적으로 꺼져
있습니다**([docs/PRIVACY.md](../PRIVACY.md)).

## 한계

- **호스팅형 앱 빌더가 아님** — 당신의 코딩 에이전트를 대체하지 않습니다. 에이전트가
  없으면 오케스트레이션할 대상 자체가 없습니다.
- **1인 빌더용** — 솔로 창업자나 CTO. 엔지니어 둘 이상이 파이프라인을 공유한다면 이
  도구를 벗어난 것입니다.
- **CI/CD 시스템이 아님** — 게이트는 로컬에서 돕니다. 머지는 여전히 GitHub Actions를
  거칩니다.
- **인증 감사가 아님** — PCI/HIPAA/SOC2 스캐폴드는 출발점이지 인증이 아닙니다.
- **결정적이지 않음** — LLM 출력입니다. 게이트 판정은 사람의 확인을 받을 가치가
  있습니다.
- **지출은 측정되지만, 귀속은 아직 에이전트별이 아님** — 비용은 에이전트의 자기
  보고가 아니라 호스트 자신의 세션 트랜스크립트에서 읽습니다. 그래서 토큰 수는
  진짜입니다. 다만 훅에 건네지는 트랜스크립트는 서브에이전트 하나가 아니라 세션
  전체를 덮기 때문에, 한 실행의 비용이 마지막에 끝난 단계에 귀속될 수 있습니다 —
  자릿수가 달라질 만큼 부풀려서. 이것이 고쳐질 때까지 에이전트별 수치는 상한선으로
  다루세요. 측정이 아예 없는 단계는 자신만만한 `$0.00` 대신 여전히 `unmeasured`를
  보여주고, 예산도 그것에는 발동하지 않습니다.
