# A/B 2026-07-29 — the graph judge against the rubric judge

**Eval:** `EVAL-security-officer-finding-gate`, holdout split, 6 cases.
**Provider:** OpenRouter, `anthropic/claude-sonnet-4` for both actor and judge.
**Samples:** 1 per arm. **Cost:** $0.71 for the two arms that count, $1.36
including the two that did not.

## What the run cost before it measured anything

The first two attempts produced numbers and measured nothing. Both are worth
recording, because both were invisible from the outside — the runner printed a
rate, the rate looked plausible, and the arms were not what the flags said.

**Bug 1 — the graph was never selected.** `loadDagFor` stripped the `EVAL-`
prefix but not the `.md` suffix, while the runner passes the file name. Every
lookup missed. The unit test passed because it called the loader with the name I
assumed the runner used, not the name the runner uses. So the first A/B compared
the rubric judge against itself and reported a one-case gap that was actor
variance.

**Bug 2 — `--judge rubric` did nothing.** `judgeMode` was threaded through
`parseArgs`, `main` and `runEvalFile`'s signature, but not passed at the one call
site in between. Both arms ran the graph. Visible only because the runner prints
which judge it picked, and both arms printed the same line.

Neither bug is exotic. Both survived a green test suite, and both were found by
running the thing end to end and reading the output rather than the code.

## The one disagreement

H6 asks the agent to raise a P1 finding with a file:line for a session token
generated by `Math.random()`.

- The rubric judge: *"The agent did not provide a specific file:line citation or
  P1 grading as required by the PASS criterion."*
- The graph answered `evidence-cited: yes` and `severity-from-context: yes`, and
  reached the full-credit leaf.

The two judges disagree about the same underlying fact — whether a citation was
present. With one sample per arm, this run cannot say which is right.

## What it does show

The claimed benefit of the graph is not a better score; it is that a
disagreement has a location. Here it does: the argument is about one question,
`evidence-cited`, and can be settled by re-reading the actor's response against
that question. The rubric verdict is a sentence, and a sentence can only be
argued with in general.

The graph cost 7.5% more ($0.366 vs $0.340). It asks up to six short questions
per case instead of one long one, and short questions with an 8-token cap are
cheap enough that the difference stays small.

## What it does not show

**Nothing about variance**, which is the whole reason the graph was built. One
sample per arm measures a single draw from each. The claim — that the same
answers always give the same score — is proven in unit tests and untested here.
Establishing it needs several samples per arm, and the actor variance that moved
both arms by one case between the discarded attempts has to be separated from
judge variance.

**Nothing about which judge is more correct.** Six cases, one disagreement.

## Next, in order

1. Repeat with `--samples 3` per arm and compare the spread, not the rate. The
   rate is not the claim.
2. Settle H6 by hand: read the actor response and answer `evidence-cited`
   yourself. Whoever is wrong tells you what to fix — the question's wording, or
   the rubric prompt.
3. The graph asks whether a citation is *present*, never whether it is *real*.
   An agent that invents a plausible `src/auth.ts:42` passes that question. Add
   the question — after the variance measurement, since changing the graph
   invalidates the comparison.
